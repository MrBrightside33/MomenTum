# Data map audit

This audit records the application write paths and current admin visibility across the
requested implementation phases. The application stores user preferences in the
`users.settings` JSON column; there is no separate user-settings table.

## Entities, writes, admin visibility, and gaps

| Entity | Current write paths | Current admin visibility | Gaps found |
| --- | --- | --- | --- |

## Raw writes and event bypasses found

The following application raw writes were found by searching PHP source for query-builder
writes, `DB::` methods, event suppression, quiet saves, and bulk model updates:

| Code path | Raw write or bypass | Assessment |
| --- | --- | --- |
| `app/Services/DueTaskReminderService.php` | `DB::table('task_activities')->insertOrIgnore(...)` | Implements a unique dedupe-key insert, but bypasses `TaskActivity` events and does not add an audit entry. |
| `app/Http/Middleware/TrackLastSeen.php` | `saveQuietly()` on `User` | Intentional one-minute write throttle; bypasses profile auditing in `UserObserver`. |
| `app/Http/Controllers/InboxController.php` | `unreadNotifications()->...->update(...)` | Bulk-updates notification read timestamps through the query builder, bypassing per-model events. |
| `app/Console/Commands/PruneAuditLogs.php` | `DB::table('audit_logs')->delete()` | Intentional retention cleanup; bypasses the append-only `AuditLog` model's delete guard. |
| `database/migrations/2026_11_12_075242_seed_default_personal_projects_for_users.php` | Reads users and uses `insertOrIgnore()` for projects. | One-time migration backfill; bypasses model events and audit logging. |
| `database/migrations/2026_11_13_024125_add_progress_tracking_to_tasks_table.php` | Query-builder updates to backfill task progress by status. | One-time schema backfill; bypasses task model observers and audit logging. |
| `database/seeders/DatabaseSeeder.php` | Uses `WithoutModelEvents`; creates demo users and audit records through factories. | Test/demo seeding intentionally suppresses model events. |
| `tests/Feature/Tasks/TaskProgressTest.php` | Direct query-builder task update. | Test-only deliberate corruption fixture; not a production write path. |
| `tests/Feature/Tasks/DeleteTaskTest.php` | `saveQuietly()` to age a soft-deleted task. | Test-only fixture; not a production write path. |
| `tests/Feature/Admin/AuditLogTest.php` | Direct query-builder count. | Read-only test assertion; not a write path. |

No `Model::withoutEvents()`, `updateQuietly()`, `increment()`, or `decrement()` production
write was found. Query-builder reads and ordinary Eloquent model writes are not listed as
raw bypasses.

## Current invariants

- `Task` uses `SoftDeletes`; normal task queries exclude soft-deleted rows.
- Admin routes are registered as GET routes behind `auth` and `admin`; the only non-GET
  route in the admin area is absent. The application-wide authenticated logout remains
  POST.
- The admin user details JSON explicitly selects safe response fields; password and
  remember-token values are hidden on the `User` model.
- Task progress/status consistency is enforced in `TaskObserver`, with a repair command
  available as `tasks:sync-progress`.
- Admin pages read from the same user, task, project, activity, and audit tables as the
  user side; there is no duplicated admin database.

## Phase 2 status and remaining gaps

`app/Support/AuditContext.php` scopes service-managed model writes so observers do not
duplicate the detailed activity and audit rows already emitted by the service. Task
comments, assignments, soft deletion, and restoration now use `TaskService`; direct
task/project/user model writes are covered by observers. Audit metadata records changed
field names and safe identifiers, not comment bodies, passwords, or notification content.

## Initial gaps to close in later phases

1. Centralize user/task/project metric definitions and reuse them on both user and admin
   pages; Phase 1 has completed this for the implemented dashboard, overview, reports,
   projects, users, and search metrics.
2. Consolidate task, project, profile, and settings writes; add observer safety nets,
   complete action-level activity/audit coverage, and touch task/project timestamps for
   related changes; Phase 2 covers the primary task paths and model observers, with the
   deduplicated reminder insert, throttled last-seen update, inbox bulk updates, migrations,
   and fixtures remaining intentional bypasses.
3. Add the requested read-only member profile, project detail, richer task listing,
   merged activity/sign-in views, and safe admin response coverage.
4. Add an aggregate-only, ETag-enabled admin pulse endpoint and interaction-aware polling.
5. Add data-health validation, safe repairs, and mismatch indicators.
6. Add the local-only activity demonstration command.
7. Add reflection tests, final documentation, and run the requested verification suite.
